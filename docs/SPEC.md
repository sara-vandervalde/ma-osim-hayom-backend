# אפיון: מה עושים היום?

האפיון שאושר לפני בניית השרת. השרת בפרויקט בנוי בדיוק לפיו.

---

## א. תיאור הפרויקט

**שם:** מה עושים היום?

**מטרה:** מאגר רעיונות לפעילויות פנאי לילדים בכל הגילאים. ההורים לא צריכים לשבור את הראש מה לעשות עם הילדים, והילדים מחפשים ובוחרים פעילות בעצמם. זה מקל על ההורים ונותן לילד עצמאות וחוויה.

**קהל יעד:** הורים וילדים בכל הגילאים.

**משתמשים:**
- **הורה:** מוסיף רעיונות, מאשר רעיונות של ילדיו ומחליט מה ציבורי.
- **ילד:** מקושר להורה שלו בהרשמה. מחפש, מסנן ומגריל פעילויות, ומציע רעיונות שממתינים לאישור ההורה.

**לעתיד, אם יהיה זמן:** תצוגת "הילדים שלי" להורה. השרת כבר תומך בה.

## ב. מסכים

| מסך | נתיב מוצע | מה מוצג | מה אפשר לעשות |
|---|---|---|---|
| התחברות | `/login` | שם משתמש וסיסמה | להתחבר |
| הרשמה | `/register` | שם משתמש, סיסמה, שם תצוגה, סוג משתמש; לילד גם שם המשתמש של ההורה | להירשם |
| רשימת פעילויות | `/activities` | כרטיסי פעילויות, חיפוש, סינון ומיון. על רעיון ממתין כתוב מי הציע אותו | לחפש, לסנן, למיין ולהגריל. הורה יכול גם לאשר, לערוך ולמחוק |
| טופס פעילות | `/activities/new`, `/activities/:id/edit` | שמונה שדות הפעילות; תיבת "ציבורי" להורה בלבד | להוסיף פעילות חדשה או לערוך קיימת. אותו טופס משמש לשתיהן |

## ג. הרשאות

כל בדיקות ההרשאה מתבצעות בשרת, לפי המשתמש שמזוהה ב־Token.

| פעולה | הורה | ילד |
|---|---|---|
| צפייה בפעילויות מאושרות של המשפחה ובפעילויות ציבוריות | ✅ | ✅ |
| צפייה ברעיונות ממתינים | של ילדיו | רק שלו |
| הוספת פעילות | ✅ מאושרת אוטומטית | ✅ נשמרת כממתינה וכפרטית |
| עריכה | כל פעילות של המשפחה (שלו ושל ילדיו) | רק שלו, כל עוד היא ממתינה |
| מחיקה | כל פעילות של המשפחה (שלו ושל ילדיו) | רק שלו, כל עוד היא ממתינה |
| אישור רעיון | של ילדיו בלבד | ❌ |
| סימון פעילות כציבורית | ✅ | ❌ |
| סינון לפי סטטוס | ✅ | ❌ |
| רשימת "הילדים שלי" | ✅ | ❌ |

רעיון של ילד נשמר כפרטי למשפחה, וההורה יכול לסמן אותו כציבורי בזמן האישור.

## ד. מסד נתונים (PostgreSQL + Prisma)

### טבלת User: משתמשים

**מטרה:** כל משתמשי המערכת, הורים וילדים.

| שדה | טיפוס | חובה | הערות |
|---|---|---|---|
| id | Int | ✅ | Primary Key, מספור אוטומטי |
| username | String | ✅ | ייחודי, 3–30 תווים, אותיות באנגלית, ספרות וקו תחתון. נשמר באותיות קטנות |
| passwordHash | String | ✅ | רק Hash של הסיסמה (bcrypt). סיסמה תקינה: 6–100 תווים |
| displayName | String | ✅ | 2–50 תווים |
| role | Enum | ✅ | `PARENT` או `CHILD` |
| parentId | Int | לילד בלבד | Foreign Key ל־User.id, חייב להצביע על הורה |
| createdAt | DateTime | ✅ | אוטומטי |

**אילוץ תקינות:** לילד חייב להיות `parentId`, ולהורה אסור שיהיה.

### טבלת Activity: פעילויות

**מטרה:** רעיונות לפעילויות פנאי.

| שדה | טיפוס | חובה | הערות |
|---|---|---|---|
| id | Int | ✅ | Primary Key |
| title | String | ✅ | 2–100 תווים |
| description | String | ✅ | 5–2000 תווים |
| category | Enum | ✅ | `CRAFT` יצירה, `GAME` משחק, `MOVEMENT` תנועה, `THINKING` חשיבה, `KITCHEN` מטבח |
| location | Enum | ✅ | `HOME` בבית, `OUTDOOR` בחוץ |
| minAge | Int | ✅ | 0–18 |
| maxAge | Int | ✅ | 0–18, גדול או שווה ל־minAge |
| durationMinutes | Int | ✅ | 1–600 |
| cost | Enum | ✅ | `FREE` חינם, `PAID` בתשלום |
| isPublic | Boolean | ✅ | ברירת מחדל: false |
| status | Enum | ✅ | `PENDING` ממתין, `APPROVED` מאושר |
| createdById | Int | ✅ | Foreign Key ל־User: מי הוסיף |
| familyId | Int | ✅ | Foreign Key ל־User: מזהה ההורה של המשפחה. השרת ממלא אותו אוטומטית |
| createdAt, updatedAt | DateTime | ✅ | אוטומטי |

**אילוצי תקינות:** טווח גילאים תקין, משך בין 1 ל־600 דקות, ורעיון ממתין תמיד פרטי.

### קשרים

- להורה יש הרבה ילדים, ולכל ילד יש הורה אחד (User ← User דרך parentId).
- למשתמש יש הרבה פעילויות שהוא הוסיף (createdById).
- למשפחה יש הרבה פעילויות (familyId).

## ה. Endpoints

כל ה־Endpoints מחייבים `Authorization: Bearer <token>`, חוץ מ־health, register ו־login.

| Method | URL | תיאור | הרשאה | תשובה בהצלחה |
|---|---|---|---|---|
| GET | `/api/health` | בדיקה שהשרת ומסד הנתונים פעילים | כולם | 200 |
| POST | `/api/auth/register` | הרשמה | כולם | 201 `{ token, user }` |
| POST | `/api/auth/login` | התחברות | כולם | 200 `{ token, user }` |
| GET | `/api/auth/me` | פרטי המשתמש המחובר | מחובר | 200 `{ user }` |
| GET | `/api/activities` | רשימה עם חיפוש, סינון ומיון | מחובר | 200 `{ activities, count }` |
| GET | `/api/activities/random` | פעילות אקראית לפי אותם סינונים | מחובר | 200 `{ activity }` |
| GET | `/api/activities/:id` | פעילות אחת, לטופס העריכה | מי שמורשה לראות אותה | 200 `{ activity }` |
| POST | `/api/activities` | הוספת פעילות | מחובר | 201 `{ activity }` |
| PUT | `/api/activities/:id` | עריכת פעילות | לפי טבלת ההרשאות | 200 `{ activity }` |
| DELETE | `/api/activities/:id` | מחיקת פעילות | לפי טבלת ההרשאות | 204 |
| PATCH | `/api/activities/:id/approve` | אישור רעיון, עם אפשרות `isPublic` | הורה של הילד | 200 `{ activity }` |
| GET | `/api/users/children` | רשימת הילדים של ההורה | הורה | 200 `{ children }` |

**פרמטרים לחיפוש ולסינון** (ב־`GET /api/activities` וב־`/random`):

| פרמטר | משמעות |
|---|---|
| `search` | מילה בשם או בתיאור |
| `category` | קטגוריה |
| `location` | מקום |
| `cost` | עלות |
| `age` | גיל הילד: מחזיר פעילויות שהגיל בטווח שלהן |
| `status` | סטטוס, להורה |
| `sort` | `duration` או `createdAt` |
| `order` | `asc` או `desc` |

**דוגמה לבקשת התחברות ולתשובה:**

```json
{ "username": "parent_demo", "password": "Demo1234" }
```

```json
{ "token": "eyJ...", "user": { "id": 1, "username": "parent_demo", "displayName": "הורה לדוגמה", "role": "PARENT", "parentId": null } }
```

**דוגמה לפעילות שחוזרת מהשרת:**

```json
{
  "id": 7, "title": "מגדל מקרטונים", "description": "...",
  "category": "CRAFT", "location": "HOME", "minAge": 4, "maxAge": 10,
  "durationMinutes": 30, "cost": "FREE", "isPublic": true, "status": "APPROVED",
  "familyId": 1, "createdBy": { "id": 1, "displayName": "הורה לדוגמה", "role": "PARENT" },
  "createdAt": "...", "updatedAt": "..."
}
```

**שגיאות** חוזרות תמיד במבנה `{ "error": { "code": "...", "message": "..." } }`.

| קוד | מתי |
|---|---|
| 400 | נתונים לא תקינים |
| 401 | לא מחובר, או Token לא תקין או שפג תוקפו |
| 403 | אין הרשאה |
| 404 | לא נמצא |
| 409 | שם המשתמש תפוס, או פעילות שכבר אושרה |

פירוט מלא, עם אפשרות לנסות כל קריאה, נמצא ב־Swagger בכתובת `/api-docs`.

## ו. התאמה לדרישות

### דרישות המערכת

| דרישה | איך היא מתקיימת |
|---|---|
| התחברות | הרשמה, התחברות ו־JWT |
| שני סוגי משתמשים עם הרשאות שונות | הורה וילד, לפי טבלת ההרשאות |
| אובייקט מרכזי אחד לפחות | פעילות |
| לפחות 5 שדות משמעותיים | 8 שדות בטופס |
| רשימת רשומות | מסך הרשימה, `GET /api/activities` |
| הוספה ועריכה | טופס פעילות, `POST` ו־`PUT` |
| קטגוריה, סטטוס או שדה בחירה | קטגוריה, מקום, עלות וסטטוס |
| חיפוש, סינון או מיון | חיפוש, 5 סינונים ו־2 מיונים |
| שמירה במסד נתונים אמיתי | PostgreSQL עם Prisma |

### דרישות React (מימוש עצמאי)

| דרישה | איפה היא נכנסת |
|---|---|
| React + TypeScript | טיפוסים ל־User ול־Activity, לפי דוגמאות ה־JSON |
| React Router | ארבעת המסכים, ונתיבים מוגנים למשתמש מחובר |
| React Hook Form + Validation | טפסי התחברות, הרשמה ופעילות, לפי כללי התקינות שבמסד הנתונים |
| React Query | שליפה, הוספה, עריכה, מחיקה, אישור והגרלה |
| Context או Redux Toolkit | Context שמחזיק את המשתמש המחובר ואת ה־Token |
| Loading וטיפול בשגיאות | מצבי הטעינה והשגיאה של React Query, והודעות השגיאה שהשרת מחזיר |
| מניעת שכפול קוד | טופס אחד להוספה ולעריכה, וקובץ אחד לכל הקריאות לשרת |
| חלוקה לקומפוננטות | למשל: כרטיס פעילות, שורת סינון, תפריט, נתיב מוגן |
